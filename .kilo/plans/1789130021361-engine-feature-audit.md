# Engine Feature Audit — Video Clipping Engine (`engine/`)

Report-only audit. Covers what is actually implemented and reachable end-to-end vs. partial/stubbed vs. missing, benchmarked against a best-in-class, niche-agnostic clip engine. No code was modified.

Scope of evidence: every `.py` module in `engine/` (main.py 2131 lines, gemini_worker.py, clip_selection.py, scene_detection.py, reframe_v2.py, layout_picker.py, split_layout.py, screencast_layout.py, active_speaker.py, camera_inset.py, punch_in.py, hooks.py, subtitles.py, ffmpeg_utils.py, layout_ranges.py, transcribe_backends.py, transcript_providers.py, security_utils.py, file_hosts.py, 21 test files), plus the SaaS wiring in `python-service/app/` (openshort_adapter.py, rendering/*, tier_service.py) that determines which engine features are actually enabled in a real run, and the frontend surface (`frontend/app/create`, `lib/constants.ts`, backend `create-job.dto.ts`).

## Section A — Currently Implemented Features

| # | Feature | Status | Evidence (file:line) | Notes |
|---|---|---|---|---|
| 1 | Moment / clip selection | **Working** | main.py:1613 `get_viral_clips`; gemini_worker.py:255-379 prompts; clip_selection.py | Two-pass Gemini pipeline: (1) one call corrects the ASR transcript AND scores ~90s candidate windows ("2-second test", hooks/conflict/surprise/emotion/payoff criteria), (2) a detail pass extracts clips from the top shortlist with copy (TikTok/IG descriptions, YT title, `viral_hook_text`). Cuts snap to word boundaries + surrounding silence (`snap_clip_to_words`, clip_selection.py:292-320). Clip count/duration driven by `CLIP_TARGET_MIN/MAX`, `CLIP_MIN/MAX_SECONDS`; SaaS sets these per-request from user options (python-service openshort_adapter.py:81-87). Signals are **transcript content only** — no audio-energy, sentiment, or audience-engagement signals beyond the LLM's judgment. Known limitation: model 503/demand spikes can still fail a job (observed live in an E2E run on gemini-2.5-flash); `GEMINI_MODEL` default is `gemini-3.1-flash-lite` (main.py:1628). |
| 2 | Scene detection | **Working** | scene_detection.py:40-148; main.py:676 | Engine default is **TransNetV2** (neural shot-boundary, 48x27 frames, SCENE_MIN_SEC merging, auto-fallback to PySceneDetect ContentDetector on any failure). **However the SaaS adapter overrides the default to `pyscenedetect`** for CPU cost (~11x faster; python-service/app/rendering/reframing.py:42). TRACK uses MediaPipe BlazeFace + `SpeakerTracker` (main.py:310: identity hysteresis, 3x sticky bonus, switch cooldown) + `SmoothedCameraman` (main.py:155: safe-zone hold, slow pan, jump-confirmation damping, scene-cut reset) + YOLO person fallback + center-hold. ## Section B — Gap Analysis vs. Best-in-Class

| # | Capability | Status | Notes |
|---|---|---|---|
| 1 | Silence / dead-air trimming | **Missing** | No audio-level silence trimming. Silence is only *consulted*: Gemini is instructed to "use silence moments for natural cuts" and `snap_clip_to_words` pads cut points into inter-word silence. Dead air inside a clip stays. |
| 2 | Filler word removal ("um"/"uh"/repeats) | **Missing** | Neither audio cutting nor caption exclusion. The LLM correction pass may tidy ASR text, but fillers are not targeted. |
| 3 | Speaker diarization | **Missing** (weak surrogate) | No transcript-level speaker labels. The visual active-speaker module answers "which of two faces is talking" for two-shots (off by default), nothing for N speakers or off-screen speakers. |
| 4 | Emotion / energy detection in speech | **Weak** | Moment selection relies entirely on LLM judgment of transcript text. An audio RMS envelope exists (used by punch-in/active-speaker), but no emotion/energy classification feeds clip selection. |
| 5 | Music-specific handling | **Missing** | No beat-sync cutting, no chorus/hook detection, no lyric-sync captions. Songs with lyrics go through the speech transcript path (a test even asserts "a song with lyrics is not sparse" — test_sparse_speech.py:35); instrumental music falls to the Gemini vision path. Punch-in (off) is the only beat-ish tool and it's speech-oriented. |
| 6 | B-roll / cutaway insertion | **Missing** | Out of scope for a pure clipping tool, but worth flagging: no stock-cutaway or b-roll insertion exists. |
| 7 | Ken Burns / auto zoom on static shots | **Weak** | `punch_in.py` is audio-beat-triggered pushes on TRACK scenes only (off by default) — not a general slow-zoom on static material, and not applied to GENERAL/wide shots. No continuous drift mode exists. |
| 8 | Multi-language (transcribe + translate/dub) | **Weak** | Transcribing non-English content: have (whisper auto-detect, Gemini copy in source language, karaoke captions in any script). Translating/dubbing output captions: missing entirely. |
| 9 | Content-type-aware processing | **Weak** | No explicit podcast/movie/music routing. Implicit adaptations only: sparse-speech → vision path (main.py:1987); optional AUTO_LAYOUT picker (off) chooses between none/screencast/split. | 10 | Output aspect ratio flexibility | **Have** | 9:16, 1:1, and 16:9 (passthrough) via `--format`/aspectRatio (python-service openshort_adapter.py:38-41). **No 4:5** (a common IG feed ratio). |

## Section C — Content-Type Readiness

### 1. Podcasts / interviews — moderate maturity, best-supported of the three
- Working well: word-level karaoke captions, face-tracked 9:16 reframe with speaker hysteresis + scene-cut reset, LLM moment selection with viral-hook copy, loudnorm audio.
- Real but dormant: SPLIT two-speaker stacking + ALTERNATE speaker-cut + the mouth-movement active-speaker gate (`SPEAKER_SIGNAL`/`SPEAKER_CUT`) — the exact features podcasts need — are implemented and unit-tested but off by default and not enabled in the SaaS deployment. With them off, a two-camera podcast is handled by generic face tracking: the camera follows the larger/most-sticky face, not whoever is actually speaking.
- Caption styles: karaoke only. No hormozi/MrBeast-style multi-word stacked-typography options (the frontend already hides unimplemented styles).
- Verdict: one env-flag flip from much better; not currently at best-in-class for multi-speaker content.

### 2. Movies / narrative content — low
- Moment selection treats movie dialogue exactly like podcast speech: the LLM judges "viral" clips by the same criteria (hooks, payoffs, 2-second test). No narrative context, no dramatic-beat/plot detection, no per-character logic.
- What helps: scene-boundary-aware reframing (cuts reset the tracker), vision fallback for silent/wordless stretches (works for action-heavy scenes), 16:9 passthrough for non-vertical exports.
- No scene-dialogue structure awareness (who speaks, off-screen dialogue vs. visible speaker), which makes multi-character scenes clip poorly.
- Verdict: usable for montage-style clips of dialogue-heavy moments; not adapted to narrative structure.

### 3. Music videos — poor (the weakest claimed content type)
- No beat detection for cutting, no chorus identification, no lyric-sync captions. A song with lyrics is processed as if it were speech; instrumental content goes through the vision path (frame-based "engaging visual moments", no musical timing).
- Punch-in (off by default) is the only music-adjacent feature, and it detects loudness peaks — not beats, not bars, not choruses.
- The product markets music videos as a target, but nothing music-specific exists in the engine today. This is the largest honesty gap between product claims and implementation.

## Prioritized Recommendation — "3 Things to Make the Engine Noticeably Better Across All Three Content Types"

1. **Turn on and wire up the layout stack that already exists** — enable `AUTO_LAYOUT=1` + `SPLIT_LAYOUT=1` + `SPEAKER_SIGNAL=1` (+ `SPEAKER_CUT` and `PUNCH_IN` after A/B) in the SaaS defaults, and fix the dead wiring so `screencast_layout.detect_content_ranges()` actually feeds `reframe_v2.render` (unlocking SCREENCAST/INSET/WIDE). This is the single highest-leverage change: the code is written, unit-tested, and measured on its own corpus (94%/92%/96% layout accuracy), but a normal production run gets only TRACK/GENERAL. Podcasts, interviews and screencasts improve dramatically; movies benefit from proper wide/scene handling. Cost: config + one call-site fix.

2. **Audio-aware moment selection: speaker diarization + energy/silence signals into clip scoring** — feed per-window speech energy, silence structure, speaking-rate and (optionally) diarization-derived speaker turns into the Gemini scoring pass (and into punch-in triggers, per punch_in.py's own TODO). This is the biggest quality lever for podcasts/interviews (cut on real conversational beats, know who is talking) and movies (dialogue structure), and removes the "LLM-only, text-only" weakness of the current selector. Deepgram offers diarization out of the box; a whisperx-style local path exists as fallback.

3. **Music mode: beat/onset detection + chorus detection + beat-snap cutting** — minimum viable: tempo/beat tracking (e.g., librosa) to snap cut points to the grid, energy-based chorus/hook section detection to weight section selection, and letting the existing word-level caption system time lyrics to vocals when present. Without this, "music videos" remains a false product claim; with it, the third target content type becomes real rather than speech-pipeline-adjacent.

Bonus (small, honest): enforce the free-tier watermark the pricing page already promises (`WATERMARK=1` for free tier), and remove the "Coming Soon"/unimplemented style options from the API surface entirely (already partially done for hormozi).

## New issues discovered during this audit (not previously flagged)

1. **SCREENCAST / INSET / WIDE layouts are dead-wired** — `reframe_v2.render(content_ranges=...)` is never called with content ranges from main.py, so those three implemented, tested layouts can never activate in any run through this pipeline (they only exist for the upstream app.py that isn't in this repo).
2. **`SCENE_ENGINE` default conflict** — engine default is TransNetV2; the SaaS adapter silently overrides to `pyscenedetect` for CPU cost. Intentional but undocumented at the engine level and confusing for operators.
3. **Watermark promise unfulfilled** — frontend pricing/settings claim free-tier watermarks, but nothing sets `WATERMARK=1` for free users; all clips ship unwatermarked.
4. **Caption style request is ignored silently** — the engine has one hardcoded auto style (karaoke); the python-service logs a fallback warning for any other requested style. Frontend now blocks unimplemented styles, but a direct API caller can still send them and get karaoke.
5. **`captionStyle`/aspect mismatch in model defaults** — `gemini_worker.py` CLI defaults to `gemini-2.5-flash` while main.py/layout modules default to `gemini-3.1-flash-lite`; example env files were previously inconsistent (now aligned to the code default).
6. **Free-tier clip-count claim is soft** — the frontend sends `clipCount` → `CLIP_TARGET_MIN/MAX`, but Gemini "may return fewer when the material does not hold them" (openshort_adapter.py:47), so users can receive fewer clips than the tier promises with no UI explanation.
7. **Orphaned "processing" jobs on crash** — a job interrupted mid-render (e.g., container restart) stays `processing` forever in the backend DB; the engine has transcript checkpoints for re-runs but nothing marks stale jobs failed.
